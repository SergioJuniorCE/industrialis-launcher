# Taste

- Expects multi-step operations that mutate user data (installs, updates, migration/reinstall paths) to be atomic and recoverable rather than in-place destruction: a verified rollback copy, automatic restore on any failure, recovery of interrupted runs on next startup, and preservation of user-modified files (configs/scripts) instead of wiping back to pack defaults. Approved a plan built around rollback + preservation over the existing backup-wipe-restore flow. Confidence: 0.5
- Wants user intent to survive updates automatically: when the user removes/excludes something from a managed bundle (e.g. deleting a mod from a modpack), that decision must persist per-instance across pack updates and be applied "automagically" on later installs/updates rather than re-asking or being silently undone. Framed as "I don't want to see it ever again". Confidence: 0.55
- Opts into being interviewed before implementation: invokes the grilling skill (`$grill-me`) to be walked through decision questions (scope, semantics, edge cases, restore path, update-time behavior) with a recommended answer for each, before any code is written. Confidence: 0.5
- Prefers the agent to keep moving autonomously through a plan instead of pausing for approval at each stage: when asked to confirm a round of design decisions, replies with "continue working" and expects it to proceed on its own recommendations, only flagging genuinely blocking questions. Confidence: 0.55
- Expects questions/interviews to be asked through the harness's interactive question tool (in T3 Code: `ask_user_question`), not as plain chat prose: called this out as a miss ("you didnt use the question tool from t3 code"), because prose rounds never reached him as answerable UI. Any skill that involves interviewing should say so as a priority rule. Confidence: 0.95
- Do not treat a decision round as answered unless he actually replied: complains ("are you gonna ask me or not, im still waiting for the questions", and in caps "YOU DIDNT USE THE QUESTION TOOL WTF") when question options auto-return or fall through, or when the questions were only dumped as numbered prose in chat. Even after a prose recap listing every question and the assumed default, he still rejects it and demands the real panels — a text recap is never an acceptable substitute for the tool. Expects the agent to notice the answers never came from him, re-issue them through the tool, and let him override the assumed defaults. Confidence: 0.8
- When a skill/agent definition is missing an instruction he relies on, expects the skill file itself to be amended (as a stated priority) rather than the behavior just being corrected once in the conversation. Confidence: 0.7
- When told to remove a deprecated name/codename, expects an exhaustive repo-wide sweep of product surfaces (installer identity, scripts, env vars, fixtures, docs, CI) rather than a minimal one-line patch; treating leftover legacy strings as incomplete work. Confidence: 0.5
